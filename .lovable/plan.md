# Phase 6.3 — Bulk Import & Media Management

Extends Stage 6.2 CMS. No redesign of existing modules. All work stays inside `src/routes/_authenticated/admin/*`, `src/components/admin/*`, `src/lib/admin/*`, plus new Supabase schema + one storage bucket.

## 1. Database (single migration)

New tables in `public`, all with GRANT + RLS restricted to staff (`is_staff(auth.uid())`), service_role full access:

- `media_library` — file rows: bucket path, mime, size, width/height, checksum (sha256), folder, tags[], alt, uploaded_by, thumbnail_path, deleted_at.
- `media_versions` — snapshot on replace: media_id, version, path, checksum, uploaded_by.
- `media_usage` — link table: media_id, question_id, usage_kind (`question|option|solution|hint|explanation|diagram`), option_index. Unique (media_id, question_id, usage_kind, option_index).
- `bulk_import_jobs` — id, created_by, source_filename, source_size, format (`csv|xlsx|json|zip`), status (`pending|validating|previewing|importing|completed|failed|cancelled|rolled_back`), totals (rows_found, rows_valid, rows_invalid, rows_imported, rows_failed, duplicates), started_at, finished_at, duration_ms, options jsonb (dedupe strategy, defaults), progress_pct, current_phase.
- `bulk_import_errors` — job_id, row_index, field, code, message, raw jsonb.
- `bulk_import_logs` — job_id, level, phase, message, meta jsonb, created_at (for realtime progress feed).
- `bulk_import_history` — job_id, question_id, action (`inserted|updated|skipped|replaced`), previous_snapshot jsonb (enables rollback).

Indexes: media_library(folder, created_at), (checksum) unique-partial where deleted_at is null; media_usage(question_id), (media_id); bulk_import_* by job_id, (created_by, created_at desc).

Rollback: single SQL function `admin_rollback_import(_job_id uuid)` (SECURITY DEFINER, staff-only) — for each history row: delete inserted questions, restore previous_snapshot on updated rows, mark job `rolled_back`.

## 2. Storage

Create private bucket `media` via `supabase--storage_create_bucket`. RLS on `storage.objects`: staff read/write, students read only referenced media through signed URLs generated by server fn.

Second private bucket `imports` for raw upload staging (deleted after job completes/fails).

## 3. Server functions (`src/lib/admin/*.functions.ts`)

All `.middleware([requireSupabaseAuth])` + staff role check via `has_any_role`.

- `import.functions.ts`
  - `createImportJob({ filename, size, format, options })` → returns job id + signed upload URL to `imports/{jobId}/source.{ext}`.
  - `startImportValidation({ jobId })` — streams file from storage, parses (CSV via `papaparse`, XLSX via `xlsx`, JSON via native, ZIP via `fflate` with manifest.json + `/media/` folder), writes rows to `bulk_import_errors` for issues, computes hashes, detects duplicates against `question_bank.question_hash` and near-duplicates via trigram (pg_trgm). Updates progress in `bulk_import_logs`. Sets status `previewing`.
  - `getImportPreview({ jobId })` — aggregated counts + first 50 rows + first 50 errors.
  - `commitImport({ jobId, dedupeStrategy })` — chunked insert (500/tx) into `question_bank`, records `bulk_import_history`. Streams progress via logs table. Uploads embedded ZIP media into `media` bucket and creates `media_usage` links.
  - `cancelImport({ jobId })` / `rollbackImport({ jobId })` (calls SQL fn).
  - `listImportJobs()` / `getImportJob({ jobId })`.

- `media.functions.ts`
  - `createMediaUploadUrl({ filename, mime, folder })` → signed URL.
  - `finalizeMediaUpload({ path, checksum, width, height, size, mime, folder, tags, alt })` — dedupes by checksum, generates thumbnail path (thumbnails generated client-side via canvas at upload time, stored under `media/thumbs/`), inserts row.
  - `replaceMedia({ mediaId, newPath, checksum, ... })` — snapshots current to `media_versions`, updates row.
  - `renameMedia`, `moveFolder`, `deleteMedia` (soft), `restoreMedia`.
  - `listMedia({ folder, q, tag, mime, unusedOnly, page, pageSize })`.
  - `getMediaSignedUrl({ mediaId })` — 1h signed url.
  - `linkMediaToQuestion({ mediaId, questionId, usageKind, optionIndex })`.

Client dependencies to add: `papaparse`, `xlsx`, `fflate`.

## 4. UI

### `src/routes/_authenticated/admin/import.tsx` — replaces placeholder
Wizard with 7 steps driven by job status. Steps:
1. **Select** — drop-zone accepting CSV/XLSX/JSON/ZIP up to 1GB, chunked resumable upload to storage via signed URL.
2. **Detect** — server infers format + column mapping.
3. **Preview** — table of first 50 rows, column mapping editor for CSV/XLSX (map source→canonical fields).
4. **Validate** — counts panel (Found / Valid / Invalid / Duplicates / Images / Est. time).
5. **Resolve** — errors table with row jump; duplicate strategy selector (Skip / Replace / Merge / Keep Both) per-row bulk.
6. **Import** — streaming progress bar (7 sub-phases from prompt) driven by Supabase realtime channel on `bulk_import_logs` filtered by job_id.
7. **Summary** — success/fail counts, download error CSV, rollback button.

Below the wizard: **Import history table** (recent 50 jobs) with status, actions (view, rollback, cancel).

### `src/routes/_authenticated/admin/media.tsx` — replaces placeholder
Two-pane layout:
- Left: folder tree + tags + filters (unused, mime, size).
- Right: virtualized grid of media cards (thumbnail, name, size, usage count). Toolbar: upload, new folder, bulk delete/move/tag.
- Detail drawer on click: full preview (SVG inline w/ zoom-pan via `react-zoom-pan-pinch`), version history, linked questions, replace, rename, delete, copy URL.
- Built-in image editor drawer (crop/rotate/resize/annotate/blur) using `react-image-crop` + canvas — outputs new file to `replaceMedia`.

Shared bits under `src/components/admin/import/*` and `src/components/admin/media/*` (Dropzone, ProgressPhases, ErrorsTable, DuplicateResolver, MediaCard, MediaDetail, ImageEditor, FolderTree).

## 5. Realtime progress

Enable Supabase realtime on `bulk_import_jobs` and `bulk_import_logs`. Client subscribes filtered by `job_id` to render live phase + progress_pct without polling.

## 6. Security

- All new tables: staff-only RLS via `is_staff(auth.uid())`. Rollback + commit fns re-verify staff inside handler.
- Storage buckets private; only signed URLs.
- Server rejects mime types outside allowlist (svg, png, jpg, webp, pdf) and file sizes > per-type caps. SVG uploads run through `DOMPurify` sanitize before storing.
- Import file scanned: reject binaries in CSV/JSON; ZIP entries validated (no path traversal, mime allowlist).
- Every admin action logged to existing `audit_logs`.

## 7. Performance

- Streaming parse (Papa's step mode, xlsx SheetJS stream, JSON via `stream-json` when >50MB).
- Chunked inserts (500 rows) with per-chunk `bulk_import_history` write.
- Virtualized tables (`@tanstack/react-virtual`) for errors + media grid.
- Signed URL caching (5m in-memory client map).
- Thumbnails 320px webp generated client-side to avoid server image processing (Worker runtime has no sharp).
